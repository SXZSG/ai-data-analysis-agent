# AI Data Analysis Agent

## Overview

AI Data Analysis Agent is a Python and Streamlit application for natural-language-driven analysis of structured tabular datasets. It combines bounded LLM-based tool selection with a deterministic execution path to support data inspection, quality diagnostics, baseline model evaluation, visualization, and report generation.

The application is designed as an inspectable decision-support workflow. It does not execute arbitrary code generated by a language model, and it reports model results with their evaluation context and limitations.

## Capabilities

- **Data ingestion:** Upload CSV and Excel files, inspect the schema, and preview records.
- **Natural-language objectives:** Specify an analysis goal and select a target column for baseline modeling.
- **Tool orchestration:** Select from registered analysis tools, validate tool calls, bound execution, record observations, and expose an execution trace.
- **Data profiling:** Summarize column types, missingness, distinct values, numeric distributions, and categorical frequencies.
- **Data-quality diagnostics:** Identify duplicate rows, constant columns, high-missingness columns, and potential numeric outliers using an IQR-based heuristic. Diagnostics do not silently modify or delete source records.
- **Baseline modeling:** Detect classification or regression tasks and compare baseline models using train-fitted preprocessing and held-out evaluation.
- **Evidence-based outputs:** Generate visualizations, a programmatic analysis summary, and downloadable Markdown and Word reports.
- **Deterministic fallback:** Run the core analysis workflow when an LLM API is not configured.
- **Automated validation:** Run integration tests and Python compilation checks through GitHub Actions.

## Architecture

1. **Load and validate data.** Read the uploaded file and inspect its structure.
2. **Establish the analysis objective.** Use the user's natural-language goal and selected target column to guide the workflow.
3. **Select and execute tools.** When a compatible LLM API is configured, use function calling to select registered tools. The runtime validates calls, limits execution, and records tool outcomes.
4. **Complete required analysis steps.** Apply deterministic workflow logic when the planner omits required outputs or the LLM service is unavailable.
5. **Evaluate and summarize evidence.** Calculate baseline metrics programmatically and produce a summary that distinguishes observed results from interpretation.
6. **Export artifacts.** Save visualizations and generate Markdown and, when available, Word reports.

The tool registry includes dataset inspection, profiling, data-quality analysis, task detection, baseline training, model evaluation, and visualization generation.

pip install -r requirements.txt

\`\`\`bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

## Run the Application

\`\`\`bash
streamlit run app.py
\`\`\`

Upload one of the example datasets in \`examples/\`, specify the analysis objective, select the target column, and run the analysis.

- \`sample_classification.csv\`: classification example; target column \`churn\`
- \`sample_regression.csv\`: regression example; target column \`price\`

## Optional LLM Configuration

To enable LLM-based tool selection and summarization, configure an OpenAI-compatible provider in the local environment. For example, create a \`.env\` file using the variable names below:

\`\`\`env
LLM_API_KEY=your_api_key_here
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
\`\`\`

The values above are examples and should be replaced with settings supported by the chosen provider. Do not commit \`.env\` files or expose API keys in screenshots, logs, or public repositories.

Without an API key, the deterministic workflow remains available. Tool-calling behavior should be verified with the selected provider before being demonstrated as an LLM-enabled feature.

## Data Handling, Safety, and Limitations

- The LLM can select only registered tools; the application does not execute arbitrary model-generated Python code.
- Data-quality findings are diagnostic warnings. Source data is not silently cleaned or deleted.
- When an LLM provider is configured, selected analysis context such as column names and aggregate profile information may be sent to that provider. Review the provider's data-handling terms before processing confidential or sensitive datasets.
- IQR-based outlier detection is heuristic and requires domain review.
- Task detection and target selection should be checked by the user before interpreting results.
- Model comparisons use baseline models and a held-out split. Metrics are not production performance guarantees; robust cross-validation, time- or group-aware leakage checks, extensive hyperparameter search, and deployment monitoring are outside the current scope.
- Language-model-generated interpretations may be incorrect. Numerical metrics are produced by the evaluation code and should be reviewed alongside the underlying data.
- The current application focuses on one tabular dataset per run. Multi-file joins, SQL sources, arbitrary Python execution, and persistent multi-turn agent sessions are not supported.
